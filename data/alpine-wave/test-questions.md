# Alpine Wave test questions

`test-questions.json` is the fixed list of questions (with expected answers) that T11 (website bot) and T12 (phone bot) are checked against, and re-checked against each time either bot changes. For each item, ask the bot the `question` (first replaying any `history` messages in order), then record what the bot actually said next to the item, as "asked X → bot said Y → source Z". An answer passes when it carries the meaning of every `must_say` fact (rewording and spoken phone formats are fine), says none of the `must_not_say` claims, follows the `behaviour` note where there is one, and for anything listed under `missing` hands off to the phone or email instead of guessing. Every `source` is a path (dots and `[n]` indexes, one path or a list) into `alpine-wave-services.json`, the only source of facts. These are expected answers, not bot transcripts. T11/T12 must not edit this list to fit their answers; if a later card changes what the bots can do (`status` in the services file), that card updates the data and the affected questions. Each item also has `applies_to`: `"both"` (ask both bots), `"website"` (website bot, T11, only) or `"phone"` (phone bot, T12, only). The website bot is checked on every `"both"` and `"website"` item; the phone bot on every `"both"` and `"phone"` item. An item is `"both"` only when every `source` it cites holds for a phone call as well as a website chat. Items whose sources are worded for the website chat only (the chat limits in `not_offered[1]`, `[2]`, `[3]` and `status.website_chat`, and the "in chat" part of `status.pricing_and_commercials`) are `"website"`, because the services file does not yet state the same limits for the phone bot. When a later card adds phone limits to the services file, a further card can re-mark those items `"both"` with the phone sources added.
